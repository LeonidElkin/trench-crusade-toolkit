description: Импортировать предоставленные PDF правил Trench Crusade в визуально проверенные Markdown и данные; использовать при замене документов или первичном импорте, а не для обычной разработки интерфейса.
---

Использовать только оригинальные PDF пользователя. Старые Markdown, каталоги, overrides и извлечения не являются источником нового импорта. Сначала читать [процедуру импорта](../../../../docs/IMPORT.md) (docs/IMPORT.md от корня проекта).

`scripts/import.py --edition <id> --out <staging> --prepare-only` создаёт читаемые изображения и посимвольные координаты. Python-окружение: tools/requirements-import.txt. Для новой редакции передать --manifest; у дополнения без номера сохранять edition: null. --resume разрешён для тех же источников.

Для дополнительного черновика Docling читать [CPU-процедуру и результаты теста](../../../../docs/DOCLING.md), общие сведения — в [официальном bundled Skill](../docling/SKILL.md). `python3 tools/docling/bootstrap.py --register-skill` устанавливает отдельное окружение и официальную ссылку через library-skills. `extract.py --manifest <manifest> --document <id> --pages N-M --out <staging>` запускать Python из tools/import-cache/docling-venv/bin/. Максимум 4 страницы, CPU, без OCR/VLM по умолчанию; --offline после подготовки весов. Markdown, native JSON, page/bbox и метаданные сохраняются отдельно. Точные команды и ограничения не дублировать из DOCLING.md.

Эталонный тест Docling: 15 ранее визуально проверенных страниц, 4 критических случая связи стоимости, не устранённых настройкой. Самостоятельный/массовый достоверный импорт не допущен. Использовать его только как дополнительный черновик отдельных диапазонов; для сложных таблиц — изображения и исходные координаты PyMuPDF. Проверять цену, знак, лимит, отрицание, исключение и принадлежность сущности. Новый заголовок конвертера не означает отдельную статью. Старую базу ради настройки Docling повторно не импортировать.

Для смыслового диапазона реально рассмотреть КАЖДОЕ изображение, выбрать порядок основных колонок, боковых блоков, таблиц и продолжений. Сохранить решения и полный текст в reconstruction/<id>/authored/. Буквица — часть слова, отдельная строка не доказывает заголовок. Полные игровые тексты и примеры сохранять; лор отделять. Значения должны иметь источник до блока/таблицы; неизвестное — явный статус.

Второй проход — повторное рассмотрение изображений и сверка текста, чисел и связей другим агентом/независимым контекстом, когда доступен. Проверяющему не предлагать считать первый результат правильным. Сохранять постраничные reports в reviews/ с хешами проверенного текста и entities. Автор не подтверждает свою работу как независимую. Если второго контекста нет, фиксировать ограничение и не подменять его тестом.

Без --prepare-only wrapper собирает базу и отчёт покрытия, отказывает при пропущенных страницах, отсутствии/устаревании независимой сверки и структурных ошибках. --author-preview создаёт только черновик, непригодный для интеграции. Рендер и сравнение извлечённых символов не выставляют визуальный статус.

Полностью готовый staging интегрировать после readyForIntegration; затем tc-validate-data и tc-check-site. Не смешивать старые/новые данные, не копировать overrides даже при совпадающем SHA PDF. Следующая редакция получает новый manifest, решения и сверку всех страниц; прежние редакции сохраняются отдельно.
