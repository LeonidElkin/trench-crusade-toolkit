# Проверка качества

Команда `npm run check` объединяет lint, strict TypeScript, валидацию данных, unit-тесты и production build. Python-аудит использует только сохранённое извлечение, не PDF. Полный запуск и E2E автоматизированы Skill `tc-check-site`.

## Области тестов

- Математика: контроль 15/36, 20/36, 1/36; таблица ранений и броня; взаимная компенсация; сумма числителей равна знаменателю; крайние модификаторы; независимый полный перебор малых пулов; 3D6/4D6 и свёртка дополнительных кубиков.
- Билдер: добавление/удаление, базовые и включённые покупки, две валюты, разные арсеналы, улучшения характеристик, доля Легионеров, обязательные профили, варианты, элитное оружие, лимиты, совместимость, наёмники, редакции, повреждённый и будущий экспорт, localStorage, ссылки с кириллицей.
- Данные: обязательные поля, уникальные ID, ссылки, страницы, диапазоны, покрытие всех страниц и сохранность чисел.
- Иллюстрации: 66 индивидуальных сопоставлений, WebP, SHA, размер, сохранённые промпты и оригиналы AI; неизменность PDF-источников. Встроенная генерация не запускается в CI.
- E2E: поиск и закладки, глубокие ссылки, шесть фракций, калькулятор, шесть бойцов с экипировкой и диагностикой, reload, экспорт/download, импорт, обмен ссылкой, валюта варианта и отказ повреждённого файла.
- E2E изображений: визуальный обзор отряда, переход к редактированию, увеличение, происхождение PDF/AI, ссылки на PDF и восстановление после reload на пяти размерах.

Playwright projects — desktop Chromium и мобильный Chromium. Отдельный sweep проверяет 1440×1000, 1280×800, 834×1112, 390×844, 320×740. Одинаковый sweep намеренно не повторяется во втором project. Скриншоты и trace при сбоях сохраняются в игнорируемых каталогах и CI artifacts.

## Визуальная проверка

Playwright MCP используется отдельно от тестового runner: загружать страницу, дождаться заголовка/lazy chunk и шрифтов, взаимодействовать по ролям, делать снимки и смотреть их. Проверять собственное переполнение страницы и локальную прокрутку таблиц; длинные имена, формы снаряжения и модальные окна. Снимок сразу после DOMContentLoaded может показывать корректное промежуточное состояние загрузки и не является завершённой визуальной проверкой.

Найденные и исправленные дефекты: сопоставление обычного пистолета/дробовика с производными, потеря полного профиля оружия при краткой ссылке варианта, фильтр закладок после лимита результатов, несовпадение base path preview и build, возврат фокуса после создания бойца.

Финальные фактические результаты локального/CI/production-прогона записываются в `HANDOFF.md`.
