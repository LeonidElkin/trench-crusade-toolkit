# Docling для будущих редакций

Проверено 2026-11-13. Текущая реконструкция 168 + 22 страниц уже завершена, независимо визуально сверена и опубликована до эксперимента. Docling не менял первичные records, игровые данные или сохранения. Это инструмент подготовки следующей редакции.

## Результат проверки

**Docling 2.150.0 не допущен к самостоятельному или массовому достоверному импорту этих PDF.** На страницах 19 и 67 основного PDF имена предметов отделяются от цен/ограничений; у Медика и Собаки стоимость оказывается в конце страницы. Сохранившиеся числа не доказывают правильную принадлежность. Эти четыре критических случая остались в автоматических черновиках. Их нельзя исправлять сопоставлением по порядковому номеру строки или заполнением из прежнего каталога.

Для текста и части профилей инструмент полезен как дополнительный черновик. Основной надёжный процесс остаётся прежним: координаты/символы/изображения PyMuPDF → авторская реконструкция → отдельная визуальная сверка → gate покрытия → производные Markdown/каталог. Docling не выставляет статус визуальной проверки и не создаёт игровые сущности автоматически.

Эталон — только новая база `reconstruction/1.6.3/authored/`, со свидетельствами независимого просмотра в `reviews/`. В тесте 15 уникальных страниц: core 4–7, 19, 22, 45, 67, 95, 125, 164 и allies 2, 4, 16, 18. Представлены колонки, красные поля, буквица, таблицы, профили, арсеналы, вариант фракции и продолжения. Соседние страницы не импортировались целиком ради теста; многополосные разделы сравниваются только в явно указанной области эталона.

## Изолированное окружение и официальный Skill

Нужен Python 3.12. CPU-only torch 2.15.0+cpu и torchvision 0.29.2+cpu устанавливаются первыми; затем Docling и library-skills. Прямые версии — `tools/requirements-docling.txt`, транзитивные — `tools/docling/constraints.txt`. В production-зависимостях сайта Docling отсутствует. MCP Server, облачные/платные API и VLM не используются.

```sh
python3 tools/docling/bootstrap.py --register-skill
python3 tools/docling/bootstrap.py --doctor
```

`--register-skill` запускает официальный `library-skills` с выбранным `VIRTUAL_ENV` и устанавливает только bundled Skill `docling`. Относительная ссылка `.agents/skills/docling` ведёт в локальный venv и начинает работать после установки зависимостей. Персональные каталоги и настройки Codex не меняются. Инструмент обнаруживает также Skill Typer; он не устанавливается. В этой сессии официальный Skill прочитан и использован; новое автоматическое обнаружение возможно со следующего сообщения.

Общие сведения не копируются в проект: [официальный DoclingSkill](../.agents/skills/docling/SKILL.md) маршрутизирует в его `references/python-sdk.md` и другие справки. Особенности Trench Crusade задаёт [tc-import-rules](../.agents/skills/tc-import-rules/SKILL.md).

До первого запуска нужны две локальные модели: layout Heron и accurate TableFormer, около 366.6 MiB. Их ревизии и SHA закреплены в `tools/docling/models.lock.json`; `models.py` загружает только перечисленные файлы. Начальный стандартный эксперимент Docling скачал также неиспользуемые fast-веса: всего около 505 MiB. Финальный скрипт их не требует. OCR-модели не загружались. Дальнейшая работа возможна офлайн:

```sh
tools/import-cache/docling-venv/bin/python tools/docling/models.py
tools/import-cache/docling-venv/bin/python tools/docling/models.py --offline
```

Первое получение пакетов/весов требует интернета; сами документы обрабатываются локально. Нужные модели, venv и логи остаются в игнорируемом `tools/import-cache/`. Для иной версии Python/Docling/весов заново проверить небольшой эталон; не выдавать старые результаты за подтверждение новой конфигурации.

## Подготовка диапазона

```sh
tools/import-cache/docling-venv/bin/python tools/docling/extract.py \
  --manifest reconstruction/1.6.3/manifest.json \
  --document core --pages 22 --threads 2 --offline \
  --out tools/import-cache/docling-example-core22
```

Для будущей редакции указать её manifest; у дополнения без номера оставить `edition:null`. Допустимы 1–4 оригинальные PDF-страницы за запуск; смысловые диапазоны с продолжением можно разбить с перекрытием. SHA и реальное число страниц проверяются до конвертации. Оригинал не режется на новый PDF, поэтому номера в provenance остаются исходными. Скрипт отказывает при непустом output и записи в production, авторские records или reviews любой редакции.

Результаты: `document.md`, полный `document.json`, `elements.json` с порядком/типом/текстом/таблицей/координатами, отдельный Markdown каждой страницы и `metadata.json` с версиями, полной конфигурацией, исходными SHA, номерами, временем/RSS и хешами файлов. Статус всегда `automatic-draft`; `success` означает завершение конвертации. Автоматический заголовок не становится статьёй.

Стандартный pipeline: CPU,2 потока, без OCR/VLM/remoteServices/генерации изображений, таблицы accurate, timeout 180 с. При плохом текстовом слое сначала подтвердить проблему на конкретном изображении и символах; OCR рассматривать отдельно только для таких страниц. OCR-режим и сканированные документы этим тестом не подтверждены.

Сверять колонки и отдельность боковых заметок; вернуть буквицу только по оригиналу; проверять все ячейки и принадлежность чисел, отрицания, исключения, имена и продолжения. Знаки нельзя стирать при нормализации. Цены в footer и столбцы без связи — повод использовать исходные координаты/визуальный проход, а не угадывать пары. Сохранять оригинальную формулировку и записывать спорные случаи в issues.

## Повторение теста и следующая редакция

```sh
tools/import-cache/docling-venv/bin/python tools/docling/benchmark.py run --resume
tools/import-cache/docling-venv/bin/python tools/docling/benchmark.py compare
tools/import-cache/docling-venv/bin/python tools/docling/benchmark.py archive
tools/import-cache/docling-venv/bin/python -m unittest discover -s tools/docling -p 'test_*.py'
python3 tools/docling/results.py --verify-only
```

`--resume` проверяет source и SHA каждого сохранённого файла, не перерабатывает успешные диапазоны. `compare` сначала проверяет независимые свидетельства основного pipeline. `comparison.json` содержит точные фрагменты/страницы и separate-table checks; совпадение не означает правильный заголовок или связь сущностей. Все 103 сигнала имеют dispositions в редакторском отчёте. Не редактировать эталон ради совпадения с конвертером.

`results.py --require-mass-ready` сейчас намеренно отказывает: осталось 4 критических случая автоматического черновика. `--verify-only` проверяет воспроизводимость сохранённых доказательств и может проходить в CI без Docling/моделей. Это разные проверки. Для повторного измерения скорости выбрать новый output; полного импорта 190 страниц не требуется.

Для следующей редакции: новый source manifest → небольшой тест макета → подготовка изображений/координат → необязательный Docling для отдельных диапазонов → авторские records → независимая постраничная сверка → `assemble.py` и реестр покрытия → схемы/ссылки/валидаторы → сравнение подготовленных каталогов через `tc-add-edition` → проверки приложения и публикация. Старые игровые данные применяются только для сравнения после независимого восстановления. Инструкции и форматы основной процедуры находятся в [IMPORT.md](IMPORT.md), без их дублирования здесь.
