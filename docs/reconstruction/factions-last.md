# Восстановление основного PDF: страницы 66–117

Автор: `factions_last`. Единственный игровой источник — `public/reference/trench-crusade-1.6.3-ru.pdf`, SHA-256 `c1ddd9579d5e7cfb5623f8b0c8528a40a96e004776831f8ccbe9e65b617879c9`.

Все 52 страницы лично рассмотрены инструментом `view_image` по отдельным рендерам PyMuPDF в масштабе 1.8; спорное слово на68 увеличено до5x. 44 страницы содержат текст, 8 являются полностраничными иллюстрациями:81,91,93,107,109,111,115,117. Рендер сам по себе не использовался как подтверждение визуальной проверки. Прежние игровые Markdown, JSON, overrides и прежние импортёры не читались.

Первичный результат: `reconstruction/1.6.3/authored/factions-last.json`. В нём97 смысловых секций, полный текст, явные исходные прямоугольники в PDF points, реестр52страниц,3фракции,6вариантов,26профилей,32особых предмета,116предложений,36улучшений (включая23гоэтические силы) и79ссылок на именованные способности. Для общих предметов сохраняются русские названия для связывания с независимо прочитанным общим арсеналом. Неснимаемые предметы и включённая в профиль броня не считаются дополнительными покупками.

`tools/reconstruction/factions_last_author.py` воспроизводит авторские решения из оригинала. Он не импортирует старые данные. Границы статей и табличные ячейки заданы явно после визуального прочтения. Скрипт отказывается применять эти решения к PDF с другой контрольной суммой. Повторный запуск скрипта не является новым визуальным проходом и может перезаписать редакторские изменения JSON; после начала независимой сверки не запускать без согласования с проверяющим.

Исправлены порядок трёх колонок66, межколоночная молитва73, продолжения Гончей88–89, тяжёлой пехоты71–72, Несчастных113–114, лор66–67 и96–97, реальные профили с несколькими строками, распавшиеся таблицы, технические пробелы после дефисов. Одиночные буквицы возвращены в начало текста. Шрифтовые изменения не становятся произвольными заголовками.
