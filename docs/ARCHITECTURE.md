# Архитектура

Браузерное приложение на React, TypeScript strict и Vite. Нет серверных компонентов, API приложения, авторизации, серверной БД и платной инфраструктуры. GitHub Pages раздаёт `dist/`.

## Слои

- `data/editions/<id>/`: Markdown, метаданные, структурированные значения и исходные ограничения.
- `tools/`: явный, воспроизводимый импорт и его аудит. Не участвуют в запуске сайта.
- `scripts/compile-content.ts`: соединяет базовый каталог с проверенными overrides, валидирует Zod и генерирует игнорируемые JSON в `src/generated/`.
- `src/domain/`: схемы, точная математика, операции над отрядом, валидация и переносимый формат. Не зависит от React, маршрутов и Pages.
- `src/data/registry.ts`: явная регистрация установленных редакций. Выбор каталога — по ID редакции и ревизии.
- `src/components/`, `src/pages/`: интерфейс и маршруты. Компоненты билдера получают каталог закреплённой редакции.

Крупный текстовый корпус загружается отдельным lazy chunk при обращении к справочнику, поиску или подробному правилу. Главная страница и билдер используют компактный каталог/индекс. Поиск — нормализованный индекс в памяти: русский регистр/ё, AND по словам, повышенный вес совпадения заголовка. Для текущего корпуса отдельный поисковый движок не нужен.

## Навигация и ресурсы

Hash-маршруты `#/rules/<encoded-id>`, `#/factions/<id>`, `#/calculator`, `#/warbands/<uuid>`, `#/import/<payload>`. Прямое открытие и перезагрузка требуют только `index.html`; серверных rewrite нет. Ссылки сущностей формируются общей функцией. Отрывки в билдере открываются native dialog с фокусом и возвратом к составу.

`APP_BASE_PATH` задаёт base только во время сборки. Локальный dev использует `/`; CI и production — `/trench-crusade-toolkit/`. Статические изображения используют `import.meta.env.BASE_URL`. Markdown-карты используют относительный путь от корня приложения.

## Состояние и приватность

Несколько отрядов — валидируемый envelope в localStorage. Неизвестная версия/повреждение не перезаписывается автоматически. При переполнении/запрете хранилища изменения остаются в памяти и доступны для JSON-экспорта; UI предупреждает о несохранении. Закладки имеют отдельный ключ.

Шаринг кодирует JSON в fragment URL: содержимое не отправляется серверу. Импорт создаёт отдельную копию и новые локальные UUID, а не перезаписывает имеющийся отряд. Для долговременного переноса основной формат — JSON, ссылка ограничена 12 000 символов.

## Решения и границы

Строгие схемы и проверки ссылок выполняются до сборки. Источник механики указывается в данных, а не угадывается компонентами. Специальные валидаторы отделены от UI. PDF отсутствуют в runtime и не нужны CI. Крупный lazy chunk справочника содержит русские тексты, а не библиотечную/серверную инфраструктуру; предупреждение Vite о его размере не означает загрузку корпуса на главной.
