# Архитектура

React, TypeScript strict и Vite; статический браузерный сайт на GitHub Pages, без бэкенда, обязательной авторизации и платных сервисов. Внешний вид сохранён; изменения интерфейса показывают восстановленные правила и исключают незаметное применение старой базы.

- `public/reference/` — два оригинальных PDF. Они доступны для сверки; runtime не извлекает из них правила.
- `reconstruction/<edition>/` — независимые авторские записи, источники, решения, сопоставления и отчёты другого проверяющего.
- `tools/reconstruction/` — явная подготовка изображений/координат и допуск по покрытию. Рендер не создаёт визуальный статус.
- `scripts/verify-reconstruction.ts` — проверка актуальных источников и подтверждений перед каждой сборкой. `reconstruct-catalog.ts` нормализует новые записи, сохраняя исходные определения и исключения.
- `data/editions/1.6.3/` — производные Markdown и каталог. `src/generated/` — игнорируемый Git runtime-вывод компилятора. Ни один слой не читает прежние overrides или старый layout.
- `src/domain/` — схемы, точная математика, операции над отрядом и валидаторы. Каталог передаётся аргументом; неоднозначное возвращает `manual`, а не успешную валидацию.
- `src/pages/`, `src/components/` — справочник, фракции, каталог, калькулятор и билдер. Профили показывают неснимаемую экипировку, способности, наследуемые правила и источники; наборы выбираются отдельно от покупок.

Hash-маршруты сохраняют работу глубоких ссылок на Pages. `APP_BASE_PATH` задаёт base сборки; внутренние изображения используют `import.meta.env.BASE_URL`. Корпус справочника загружается лениво. Ключевые слова связываются с отдельными статьями, полные таблицы и оригинальные схемы сохранены.

Визуальные назначения отделены от механик в `data/visuals/`. Существующие66портретов пересопоставлены новым ID, четыре отсутствия обозначены явно. Новые изображения ради реконструкции не создавались.

Сохранения v2 хранят точную редакцию и ревизию, покупки, улучшения и `loadouts` (личный набор, профиль, способность, привязанный алхимик). Старый ключ v1 остаётся физически сохранённым; UI сообщает несовместимость. Импорт v1 отклоняется явно. Экспорт/ссылки/дублирование работают с v2 и новыми UUID, включая внутренние связи. Повреждённое хранилище не перезаписывается автоматически.

Публикация: checks → Actions artifact → Pages → production E2E и Playwright MCP. `public/recover.js` сохраняет восстановление старого HTML при удалённом lazy chunk. Подробности: `DEPLOYMENT.md`. Будущий Docling — отдельный локальный инструмент подготовки, не production-зависимость и не замена проверенной базы без конкретной ошибки.
