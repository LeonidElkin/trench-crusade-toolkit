# Иллюстрации

Пользователь разрешил публиковать исходные PDF и использовать найденные изображения. Для любых недостающих иллюстраций разрешён встроенный Codex `image_gen`, без отдельного платного API, сторонних платных сервисов и OPENAI_API_KEY. Хорошие существующие изображения сохраняются. Это относится ко всему сайту, не только к портретам.

## Источники и связь с бойцами

`data/visuals/<edition>/portrait-plan.json` — проверенное сопоставление стабильных `unitId` с изображениями и их происхождением. PDF-объекты имеют документ, страницу и xref; генерированные — оригинал и файл полного промпта. Промпты опираются на адресные описания Markdown/JSON именно этой редакции; свободные детали внешности считаются художественной интерпретацией, а не новыми правилами.

`portraits.json` — производный индекс WebP, размеров и SHA-256. Эти визуальные метаданные не меняют замороженные характеристики и стоимость старых ревизий. Сайт не сопоставляет бойцов по отображаемому имени. Отряды продолжают хранить только стабильные игровые ID.

Исходные AI-изображения хранятся в `assets/generated/<edition>/`; в публикацию попадают только оптимизированные файлы `public/portraits/<edition>/`. Служебные каталоги Codex не нужны для работы или повторной сборки. Промпты в `data/visuals/<edition>/prompts/`. Повторная генерация не гарантирует побитового совпадения; сохранённые оригиналы позволяют детерминированно восстановить веб-версии.

## Повторяемые команды

```sh
npx tsx tools/manage-portraits.ts status --edition 1.6.3 --check
npx tsx tools/manage-portraits.ts add-generated --unit sultanate.sapper --file /path/to/image.png
PDF_PYTHON=/path/to/venv/bin/python npm run assets:portraits -- 1.6.3
npm run data:validate
```

`status` показывает отсутствующие и общие изображения; `--check` возвращает ненулевой код при неполном покрытии. `add-generated` копирует существующий результат встроенного инструмента, сохраняет происхождение, оптимизирует обе версии и обновляет сопоставление. Он отказывается заменять уже существующий индивидуальный портрет. Перед ним должен существовать полный промпт `<unit-id-with-hyphens>.md`.

`assets:portraits` явно извлекает проверенные PDF-объекты, восстанавливает исходные альфа-маски и оптимизирует их вместе с сохранёнными AI-оригиналами. Для PDF требуется Python с `tools/requirements-import.txt`; Sharp закреплён lockfile. Команда не генерирует новые изображения. Обычная сборка, CI и запуск никогда не извлекают PDF и не вызывают генерацию.

WebP для просмотра ограничен 840×1000, миниатюра — 280×320, без увеличения исходника. Lazy-loading, `decoding=async`, фиксированные области и `object-fit:contain` сохраняют читаемый силуэт; полный файл загружается только при увеличении. Все изображения локальные, горячих ссылок на чужие серверы нет.

## Контроль

`npm run data:validate` проверяет Zod, покрытие каждого профиля, уникальность сопоставления, существование файлов, контрольные суммы, формат и бюджет размера, источник и сохранённый промпт/оригинал для AI. Изображения не объявляют обязательную экипировку: в обзоре отряда явно сказано, что рисунок не меняется при покупках.

Новый портрет проверять визуально: соответствие фракции, описанию и разрешённой экипировке, один персонаж, читаемый силуэт, отсутствие текста/водяных знаков. Проверить карточку, увеличение, пополнение, состав и обзор на desktop и телефоне через Playwright MCP; E2E сохраняет сценарий обзора, provenance и восстановления отряда.

Первая подборка: 66/66 профилей, 55 PDF-иллюстраций и 11 AI-изображений. Повторная подготовка всех файлов из сохранённых источников проверена: метаданные и SHA всех WebP совпали побитово. Общий размер полных версий и миниатюр — около 6 МБ; исходные PNG не загружаются сайтом.
