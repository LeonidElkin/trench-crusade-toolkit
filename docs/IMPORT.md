# Визуально-текстовая реконструкция PDF

PDF разбираются только явной командой; dev/build/CI не извлекают правила. Оригиналы в public/reference/: основной документ — **168 страниц**, «Союзники и Наёмники» — **22**. У дополнения edition=null: номера редакции нет. Перевод — Мастерская Кетсу.

Старый pipeline определял заголовки/порядок по извлечению, затем сверял результат с тем же извлечением. Это не доказывало верность колонок, абзацев, таблиц и растровых элементов. Старые Markdown, layout, каталоги и overrides исключены из входов реконструкции.

## Подготовка

```sh
python3 -m venv /tmp/tc-reconstruction-venv
/tmp/tc-reconstruction-venv/bin/pip install -r tools/requirements-import.txt
/tmp/tc-reconstruction-venv/bin/python .agents/skills/tc-import-rules/scripts/import.py --edition 1.6.3 --out tools/import-cache/next-import --prepare-only
```

Manifest: reconstruction/1.6.3/manifest.json. Для следующей редакции создать собственный manifest с её документами и реальным числом страниц. Wrapper принимает --manifest, --authored, --reviews. Импорт в data/editions запрещён: сначала полностью проверенный staging.

prepare.py рендерит все страницы при180dpi и сохраняет исходный поток символов, координаты блоков/строк/символов, шрифты, выделения и геометрию векторных объектов. Адреса bNNN.lNNN.sNNN относятся к исходному PDF; порядок потока не объявляется порядком чтения. SHA документа/изображения защищают от устаревшего кеша. --resume проверяет источники; повреждённые изображения создаются заново.

## Авторский проход

Работать смысловыми диапазонами, с перекрытием соседних страниц для продолжений.

1. Открыть каждое изображение через view_image; мелкий текст/таблицы читать увеличенным рендером/crop. Контактный лист — навигация, не прочтение правил.
2. Записать области и порядок: основные колонки, красные примечания, таблицы, подписи, иллюстрации и буквицы. Близость и шрифт сами по себе не определяют связь или заголовок.
3. Восстановить полные абзацы, продолжения, выделенные термины, списки/таблицы. Не сокращать условия, числа, исключения, примеры. Лор отделять от механики.
4. Сохранить первичный JSON: sections с полным Markdown, entities с характеристиками/источниками, pages с решениями для каждой страницы и issues. Старые данные не использовать для заполнения пробелов.
5. Титулы/иллюстрации/служебные страницы учесть с явной причиной отсутствия статьи. Схемы сценариев являются игровыми данными: сохранить изображение из оригинала с PDF/bbox/SHA.

Авторские решения: reconstruction/<id>/authored/. tools/reconstruction/*_build.py, *_author.py — рецепты первоначального набора по оригиналу и выбранным областям, а не распознаватели будущей редакции. После исправлений проверяющего первичен JSON: не перезапускать рецепт поверх него.

## Независимая сверка

Другой агент/контекст повторно открывает каждую оригинальную страницу и сравнивает полный текст/сущности: порядок, предложения, таблицы, числа, ограничения, исключения, профили, связи, соседние продолжения. Не давать готового вывода о правильности. Сравнение извлечённых символов — только подсказка.

reviews/*.json хранит reviewer, document, authorFile, pages с pdfPage/status/notes/sectionHashes, findings и entitiesSha256. SHA текста секции — UTF-8 Markdown; entities — JSON UTF-8 с ensure_ascii=False, sort_keys=True, separators=(',', ':'). Хеши снимать после исправлений. Изменение текста/сущностей аннулирует подтверждение. Авторский visualInspection и независимый verified — разные состояния; скрипты их не выставляют.

Машина проверяет наличие/целостность свидетельства, но не доказывает факт прочтения изображения. Ответственность за честный статус у редактора. При ограничениях сохранять pending и сообщать о них.

## Сборка и покрытие

```sh
/tmp/tc-reconstruction-venv/bin/python tools/reconstruction/assemble.py --manifest reconstruction/1.6.3/manifest.json --authored reconstruction/1.6.3/authored --reviews reconstruction/1.6.3/reviews --out tools/import-cache/assembled-1.6.3
```

coverage.json создаётся и при отказе: все PDF-страницы, печатный номер (null, если отсутствует), тип, файлы, чтение областей, автор, визуальный статус, независимая сверка, проблемы. readyForIntegration разрешён только при полном покрытии, актуальных отчётах и отсутствии структурных ошибок. --allow-pending-review/--author-preview — только черновик, всегда readyForIntegration=false.

Ошибки: пропущенные/лишние/дублирующиеся страницы, пустой результат содержательной страницы, сломанные связи, однобуквенные заголовки, неровные таблицы, Unicode replacement, отсутствующие источники, повторяющиеся ID. Эвристики отдельно отмечают короткие статьи, подозрительные заголовки, мягкие переносы и незавершённые абзацы. Рассмотреть их вручную; короткое ключевое слово может быть корректным.

Markdown и собранный каталог производны от новых авторских записей. Production получает только полностью проверенную новую базу. Старые fallback/overrides не копировать. До публикации: схемы/ссылки/ограничения, unit, production build, E2E и Playwright MCP локально/Pages. Незавершённую работу сохранять в ветке/HANDOFF, production частично не заменять.
