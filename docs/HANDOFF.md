## Docling: завершённый эксперимент и будущая работа

- Изолированный `tools/import-cache/docling-venv`, Python 3.12.3, Docling 2.150.0, CPU torch 2.15.0+cpu/torchvision 0.29.2+cpu, library-skills 0.0.20. Версии/constraints и модели с commit/SHA закреплены в `tools/docling/`. Ни production-зависимостей Docling, ни MCP Server, ни облачной обработки нет.
- Официальный bundled Skill зарегистрирован через library-skills: `.agents/skills/docling` — относительная ссылка в venv. `python3 tools/docling/bootstrap.py --register-skill` восстанавливает установку; `--doctor` проверяет CPU. Проектный `tc-import-rules` обновлён и прошёл quick_validate; реальный малый импорт через него проверен на allies 16.
- Эталон **15 уникальных ранее визуально проверенных страниц** из обоих PDF. 39 разделов/273 контрольных фрагмента, 170 точных совпадений и 103 сигнала с редакторскими dispositions. Для диагностики повторно открыты 8 изображений оригинала; это не новая независимая сверка остальных 7, эталон которой уже существует.
- CPU: 2 потока, суммарно 105.526 с, пик 1587.8MiB. Финальные необходимые веса 366.6MiB; исходный стандартный запуск загрузил также fast-веса (~505MiB всего). OCR/VLM/remote выключены.
- **Самостоятельный/массовый достоверный импорт Docling НЕ ДОПУЩЕН**: 4 критических случая связи стоимости (арсеналы core 19/67 и цена союзников 2/18). Отключение reading-order separators на двух проблемных страницах ничего не исправило. Использовать Docling только как дополнительный черновик отдельных диапазонов; основной надёжный процесс — изображения/символы/координаты PyMuPDF + авторские records + независимый визуальный gate.
- Offline core 22, pinned-models core 22 и Skill smoke allies 16 воспроизвели исходные Markdown/native JSON байт-в-байт. **9 тестов** защищают знаки, отрицания, лимиты, provenance, SHA, реальные страницы и запрет записи черновиков в production/reviews.
- Полные метаданные, Markdown, сжатый lossless native JSON и отчёты — `reconstruction/docling-benchmark/`. Venv/веса/изображения/лишние логи игнорируются Git. `python3 tools/docling/results.py --verify-only` проверяет сохранённые доказательства в CI без моделей. `--require-mass-ready` намеренно отказывает из-за 4 критических случаев; это честный отрицательный результат эксперимента, не незавершённая реконструкция сайта.

Процедура/ограничения: `docs/DOCLING.md`; весь импорт/coverage/independent review — `docs/IMPORT.md`. Для следующей редакции новый manifest, малый тест нового макета, затем авторский/независимый проход. Старые каталоги служат только последующему сравнению (`tc-add-edition`), не заполнению правил. Количественная экономия токенов и OCR/сканы не подтверждены этим тестом.
