# Рабочие источники данных

`data/editions/1.6.3/` содержит первую реальную редакцию проекта. Не создавать демонстрационные редакции.

| Файл                             | Назначение                                                                             |
| -------------------------------- | -------------------------------------------------------------------------------------- |
| `sources.json`                   | Названия PDF, SHA-256, страницы; у дополнения edition = null                           |
| `articles.json`                  | Стабильный ID, логический раздел, путь Markdown и страницы                             |
| `content/*.md`                   | Канонический редактируемый русский текст, таблицы и схемы                              |
| `catalog-base.json`              | Численные значения и связи, детерминированно полученные из извлечения                  |
| `catalog-overrides.json`         | Проверенные сопоставления, исключения, улучшения и специальные варианты                |
| `layout.json`                    | Свидетельства извлечения: блоки, координаты, таблицы; читать адресно                   |
| `import-audit.json`              | Покрытие всех 190 страниц, включая иллюстрации                                         |
| `content-audit.json`             | Проверка сохранности букв/цифр и чисел в Markdown относительно извлечения              |
| `catalog-extraction-report.json` | Результат исходного автоматического сопоставления; один unresolved исправлен overrides |
| `edition-lock.json`              | Контрольная точка опубликованной ревизии                                               |

Текст не дублируется в каталоге: у профилей/предметов/покупок есть `ruleId`. Числа в Markdown — отображение источника; расчёт выполняется по каталогу, который получается из таблиц и проверенного слоя. Не менять стоимость только в одном отображении: обновить источник и проверенный каталог согласованно, с указанием причины.

`Item` описывает оружие/броню/снаряжение; `Offer` — покупку в конкретном арсенале со своей ценой, валютой, лимитом и ограничениями. Один предмет может стоить дукаты у одной фракции и Славу у другой. `Unit` хранит базовый профиль и неснимаемые предметы, уже включённые в стоимость. Альтернативы с отличающимися характеристиками представлены отдельными стабильными ID. `Upgrade` хранит стоимость, доступность, группу взаимоисключения, изменения и ссылку. Гоэтические силы дополнительно привязаны к греху.

Схемы: `src/domain/schema.ts`. Межсущностные ссылки, страницы, уникальность ID, обязательные поля и непротиворечивые диапазоны проверяет `scripts/validate-data.ts`. Форматы исходных строк характеристик сохраняются (`+1D`, `6”/пехота`), а изменения применяются только к явно численным характеристикам.

Неоднозначности не превращать в вымышленные числа. `unresolved`, `manualCheck` и диагностические constraints должны оставаться видимыми пользователю. Автоматический аудит не доказывает, что логическая интерпретация каждого абзаца верна; обязательна адресная сверка с исходными страницами при изменении механики.
