# Trench Crusade Toolkit

Русский статический компаньон Trench Crusade. Единственный разрешённый удалённый репозиторий: `LeonidElkin/trench-crusade-toolkit`. Пользователь разрешил обычные коммиты, push в main и настройку GitHub Pages; запрещены force push, переписывание истории, изменения других репозиториев и глобальной конфигурации GitHub.

## Постоянные ограничения

- Пользователь 2026-11-10 явно разрешил использовать и публиковать тексты и изображения для этого проекта без повторного согласования. Отдельно подтверждены иллюстрации и схемы PDF. Сохранять сведения об источниках и авторах. В README обязательно указывать: проект некоммерческий. Это разрешение не расширяет доступ к другим репозиториям или аккаунтам.

- Пользователь попросил публиковать исходные PDF, указывать перевод Мастерской Кетсу и полную разработку проекта AI-агентами. README не должен ссылаться на личные локальные каталоги пользователя.
- Источники механик редакции 1.6.3 — только PDF в `public/reference/` (пути в import-manifest). Trench Companion — только образец интерфейса и изображений. Не подставлять правила из других редакций.
- Не исправлять источник молча. Неоднозначности и непроверенные механики фиксировать в данных и `docs/KNOWN-ISSUES.md`; непроверенная проверка не означает валидность отряда.
- Английские игровые термины сохранять на английском и выделять жирным; выделенные русские термины сохранять на русском.
- PDF разбираются только явной командой импорта. Рабочие источники — Markdown и JSON в `data/editions/`. У каждой сущности должны быть стабильный ID и страницы источника.
- Только браузер, без бэкенда, платных сервисов и обязательной авторизации. Дукаты и Слава — независимые валюты.
- Данные, доменная логика и UI раздельны. Старые редакции и отряды не мигрировать автоматически.
- TypeScript strict, React, Vite; hash-маршруты; base path задаётся окружением сборки. GitHub Pages публикуется Actions после проверок.
- Секреты не читать и не печатать. Использовать существующий GH_TOKEN через gh; GitHub MCP только для чтения, gh/Git для записи. Playwright MCP обязателен для визуальной проверки локального и опубликованного приложения.

## Работа

Начать с `docs/HANDOFF.md`. Команды после установки зависимостей: `npm ci`, `npm run dev`, `npm run check`, `npm run build`, `npm run test:e2e`. Перед push проверить состояние origin. Значимые решения и незавершённую работу сохранять в документации; не раздувать этот файл журналом.

Проектные навыки: `.agents/skills/`. Архитектура, импорт, модель данных и публикация описаны в `docs/`. Повторяемую работу выполнять скриптами; не перечитывать весь корпус PDF для локального изменения.
